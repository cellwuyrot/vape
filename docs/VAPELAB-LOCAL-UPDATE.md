# VAPELAB — локальное применение обновления

## Что изменилось

- Исправлено соответствие CSS-переменных светлой и тёмной тем CRM, чтобы старые формы, таблицы и разделители не теряли цвета при переключении.
- Вход подписан «Личный кабинет»; убрана лишняя подсказка под заголовком. Возврат из CRM в магазин и обратно не удаляет сессионный токен.
- Увеличен размер ссылок навигации публичной витрины.
- Убраны переходы из публичных карточек и разделов на исходный сайт. Telegram-контакт оставлен.
- Сохранён исходный OriginKit Hero 58 с чёрно-циановой палитрой; тексты Hero поддерживают значения из настроек.
- Администратор и главный администратор могут открыть на главной «Редактировать сайт» и менять основные надписи и описания.
- Добавлены страницы «Политика конфиденциальности» и «Доставка». Они изначально черновые; текст не раскрывается посетителям и не индексируется до публикации и подтверждения проверки.
- Витрина показывает товары на страницах категорий с пагинацией; каждая карточка ведёт на отдельную страницу товара.
- В CRM можно назначать товару несколько категорий, редактировать категории, фильтровать товары и загружать каталог через мастер XLSX/CSV.
- Добавлена загрузка папки фотографий. Имя файла без расширения должно точно совпасть с названием товара, его slug или SKU. Поддерживаются JPG, PNG и WebP. Неоднозначные совпадения не назначаются автоматически.
- Добавлены рекомендации по категории, бренду, типу, формату, SEO-ключам и контексту последних просмотренных страниц. История хранится локально в браузере; постоянный профиль просмотра на сервере не создаётся.

## Обновление существующей локальной копии

1. Сохрани свою текущую папку проекта как резервную копию.
2. Распакуй содержимое архива поверх существующей папки проекта `вейплаб`, разрешив замену файлов.
3. Не удаляй и не заменяй `.env`, каталог `data`, `node_modules` и собственные загруженные файлы `public/uploads`.
4. Из корня проекта выполни:

```cmd
npm run build:storefront
```

5. После успешной сборки запусти backend:

```cmd
npm start
```

6. Открой `http://localhost:3000`.

Второй отдельный сервер Vite для обычного локального просмотра не нужен: backend отдаёт production-сборку из `public/react-app` и обслуживает API на том же порту.

Если в новой чистой копии нет зависимостей витрины, сначала выполни:

```cmd
npm ci --prefix storefront-react
```

Затем повтори `npm run build:storefront` и `npm start`.

## Миграция базы

Добавлена миграция `010_storefront_editor_legal.sql`. Она запускается автоматически при старте backend и создаёт недостающие страницы `privacy` и `delivery` в статусе черновика. Существующие записи с такими slug не перезаписываются. Перед первым запуском обновлённой версии рекомендуется сохранить резервную копию каталога `data`.

## Импорт XLSX и фотографий

- В CRM открой «Витрина» → «Товары» → «Импорт XLSX / CSV».
- Проверь сопоставление колонок в предпросмотре и сначала используй пробный прогон.
- После импорта товары создаются черновиками и могут быть распределены по нескольким категориям.
- Для фотографий используй кнопку загрузки папки на вкладке товаров. Например, для товара со slug `mok-fwrd-siniy` подойдёт файл `mok-fwrd-siniy.webp`.
- Если в системе несколько товаров с одинаковым совпадающим названием или SKU, фотография будет отмечена как неоднозначная; она не прикрепляется наугад.

## Редактирование сайта и документов

- На главной странице вошедшему `admin` или `superadmin` доступна кнопка «Редактировать сайт».
- В CRM открой «Витрина» → «Страницы», чтобы заполнить политику конфиденциальности и условия доставки.
- Юридическая публикация требует заполненного текста и отдельного подтверждения проверки. Текст правовых документов в архиве не придуман и не подменяет юридическую проверку.
