# Дорожная карта развития RuCRM

Позиционирование неизменно: не «комбайн», а быстрая CRM с полным российским контуром
и честной ценой. То, что другие делают лучше, — берём интеграцией, а не своим огрызком.

## Фаза 0 — Фундамент (реализовано)

Без этого дальше строить опасно: каждая следующая фаза добавляет данные, которые нельзя потерять.

- Версионные миграции схемы: каталог `migrations/`, таблица `schema_migrations`,
  накат недостающих версий при старте, контрольные суммы против правки применённых файлов.
- Второй драйвер хранилища — PostgreSQL. Включается переменной `DATABASE_URL`, SQLite остаётся
  умолчанием для демо. Клиент протокола написан на стандартной библиотеке, зависимостей по-прежнему ноль.
- Файловое хранилище вложений: S3-совместимое (Яндекс Object Storage, VK Cloud, Selectel)
  с локальным каталогом как запасным вариантом при недоступности объектного хранилища.
- Автоматические резервные копии базы и файлов по расписанию, с обязательной проверкой
  восстановления: архив разворачивается и сверяется с манифестом сразу после снятия.
- Структурированные логи в JSON с идентификатором запроса, метрики Prometheus с временем
  ответа, раздельные эндпоинты живости `/api/health` и готовности `/api/ready`.
- CI на каждый коммит: собственный линтер, тесты на SQLite и PostgreSQL, матрица версий Node,
  сборка образа с проверкой выхода в готовность.

Эксплуатационные инструкции — `docs/OPERATIONS.md`.

## Фаза 1 — Рутина менеджера (реализовано)

Самая недооценённая фаза: без неё менеджеры возвращаются в блокнот и Excel.

- **Задачи и календарь.** Задача из карточки клиента, сделки и диалога; типы «звонок»,
  «встреча», «письмо», «сообщение»; сроки и напоминания; выборки «сегодня», «просроченные»,
  «неделя»; календарь недели. Напоминания рассылает планировщик, повтор исключён флагом в базе.
- **Несколько воронок.** Продажи, повторные продажи, сервис — у каждой свой набор стадий,
  переключатель над доской, новая воронка создаётся из настроек.
- **Обязательные поля на стадии и причина отказа из справочника.** Проверка выполняется
  на сервере по итоговому состоянию сделки, а не в форме, — обойти её через API нельзя.
- **Дубли.** Нормализация телефона, почты и ИНН; подсказка при вводе, пакетная проверка базы,
  склейка с переносом сделок, заказов, диалогов, задач и ленты. Донор помечается
  присоединённым, а не удаляется: карточку с ПДн нужно уметь показать по запросу субъекта.
- **Импорт из Excel и CSV** с сопоставлением колонок, предпросмотром и пробным прогоном,
  включая распознавание выгрузок amoCRM и Битрикс24. Разбор xlsx — свой, на `node:zlib`.
- **Шаблоны быстрых ответов** по клавише «/» и `Ctrl + Пробел`, вложения в переписке.
- **Печатные формы:** коммерческое предложение, счёт, договор, акт. Подстановка реквизитов,
  НДС, сумма прописью; бланк правится в настройках. Вывод в PDF — штатной печатью браузера.
- **Лента активности** в карточке клиента: сделки, стадии, задачи, звонки, заметки, заказы,
  документы и переписка из всех каналов одним потоком.

## Фаза 2 — Автоматизация (4–6 недель)

То, ради чего покупают amoCRM. Конструктор важнее набора готовых сценариев.

- Движок правил: событие — условие — действие. События: новое обращение, смена стадии,
  отсутствие ответа N часов, дата поля, поступление оплаты. Действия: поставить задачу,
  отправить сообщение или письмо, сменить стадию, назначить ответственного, вызвать вебхук.
- Визуальный редактор сценариев на канве. Обязательно: журнал срабатываний и тестовый прогон —
  автоматизация не должна работать как чёрный ящик, это главная претензия к роботам Битрикса.
- Распределение входящих обращений: по очереди, по загрузке, по каналу, по ответственному за клиента.
- SLA: время первого ответа и время решения, эскалация руководителю, счётчик в инбоксе.
- Рабочее расписание и часовые пояса клиента: автоответ вне рабочих часов, запрет ночных звонков.
- Сценарный бот квалификации: собирает бюджет, сроки и задачу до передачи менеджеру.

Задел уже есть: `server/scheduler.js` умеет фоновые задачи, `server/activity.js` пишет события,
из которых складывается журнал срабатываний.

Техническое задание фазы — `docs/PHASE-2-AUTOMATION.md`: модель правила, список событий,
условий и действий, схема миграции `004`, порядок исполнения, требования к журналу
и тестовому прогону, распределение, SLA, расписание, бот и план работ по неделям.

## Фаза 3 — Российский контур (6–8 недель)

Здесь мы обгоняем amoCRM, у которой это слабое место, и приближаемся к Битрикс24.

| Интеграция | Что даёт | Как подключать |
|---|---|---|
| Дадата и ЕГРЮЛ | Автозаполнение реквизитов по ИНН, проверка контрагента | REST API, кнопка в карточке компании. Быстрая победа — делать первой |
| 1С (Бухгалтерия, УТ, УНФ, ERP) | Контрагенты, номенклатура, заказы, оплаты | HTTP-сервисы или OData, поле `orders.external_1c_id` |
| ЭДО: Диадок, СБИС, Такском | УПД и счета-фактуры из карточки заказа, статусы подписания | REST API оператора, поле `orders.edo_document_id` |
| Онлайн-кассы и ОФД (54-ФЗ) | Фискализация чека при оплате | АТОЛ Онлайн, Эвотор, Штрих-М; поле `orders.receipt_fiscal_id` |
| Банки: Сбер, Т-Банк, Альфа | Выписки по расписанию, автоматическая разноска оплат, ссылки на оплату | Банковский API |
| Электронная подпись (63-ФЗ), «Честный знак» | Подписание документов, коды маркировки | Поле `products.marking_required` уже есть |

## Фаза 4 — Телефония и каналы (4–6 недель)

- Телефония: Манго, МТС Exolve, Telphin, Asterisk. Звонок из карточки в один клик,
  всплывающая карточка при входящем, запись разговора в ленте, пропущенный — сразу задача.
- WhatsApp Business API напрямую, помимо агрегатора: меньше зависимости от посредника.
- E-mail как полноценный канал: IMAP и SMTP, переписка в карточке, ответ из инбокса.
- ВКонтакте и MAX напрямую, чаты Ozon и Wildberries.
- Виджет онлайн-чата и конструктор лид-форм с готовым кодом вставки.
- Единый профиль клиента: обращения с одного номера из разных каналов — одна история.

## Фаза 5 — Аналитика и маркетинг (4–6 недель)

- Сквозная аналитика: UTM-метки из формы сохраняются в сделке, отчёт по источникам
  с выручкой и стоимостью лида, Яндекс Метрика и Директ.
- Отчёты: конверсия по стадиям, длительность стадии, причины отказа, эффективность
  менеджеров, план-факт по выручке. Данные для этого уже пишутся: `stage_changed_at`,
  `lost_reason_id`, лента активности.
- Когортный анализ и RFM-сегментация базы для повторных продаж.
- Конструктор дашбордов: экран руководителя и экран менеджера.
- Рассылки по сегментам через Unisender и Sendsay, с учётом согласий и отписок.
- Экспорт любого отчёта в Excel и выгрузка в DataLens и Power BI через API.

## Фаза 6 — Платформа (4–6 недель)

- Публичный REST API с ключами, OpenAPI и версионированием. Обещание прямое:
  без лимитов на количество интеграций и без доплат за API.
- Исходящие вебхуки на события системы.
- Конструктор произвольных полей и воронок без программиста (набор стадий уже настраивается).
- Права по подразделениям и иерархии: менеджер видит своё, руководитель — отдел, директор — всё.
- Безопасность: двухфакторная аутентификация, SSO, ограничение массового экспорта базы
  с алертом руководителю — защита от увода базы при увольнении.
- Мобильный доступ: PWA с офлайн-очередью и push. Нативное приложение — только если PWA упрётся.
- Каталог плагинов: описанный контракт расширения, чтобы интеграторы не форкали ядро.

## Фаза 7 — AI на российских моделях (4–6 недель, параллельно)

Модели — YandexGPT или GigaChat: работают внутри РФ, что снимает вопрос трансграничной передачи ПДн.

- Саммари длинной переписки и звонка в карточке клиента.
- Подсказка следующего шага и черновик ответа — с обязательным подтверждением человеком.
- Скоринг вероятности закрытия на истории собственной базы.
- Автозаполнение полей сделки из текста переписки: бюджет, сроки, потребность.
- Расшифровка звонков с поиском по тексту и анализом возражений.
- Отдельный контур приватности: переключатель, какие данные уходят в модель,
  и запись каждого обращения к ней в журнал ПДн.

## Чего сознательно не делаем

Битрикс24 проиграл в удобстве именно потому, что делал всё сразу. За рамками остаются:
корпоративный портал и лента новостей, HR и учёт рабочего времени, конструктор сайтов
и интернет-магазин, видеоконференции, полноценное управление проектами с диаграммой Ганта,
складской учёт. Вместо этого — интеграции с теми, кто делает это лучше: МойСклад, 1С.

## Как меряем успех

- Доля обращений с ответом в течение 15 минут — выше 90 %.
- Время открытия карточки сделки — ниже 300 мс на базе в 100 000 записей.
- Доля сделок с заполненной причиной отказа — выше 95 % (обеспечено обязательным полем).
- Количество ручных действий на одну сделку — снижать от фазы к фазе.
- Доля сотрудников, заходящих в систему ежедневно.
- Время внедрения для новой компании — до одной недели (импорт базы закрывает главный барьер).

## VAPELAB — актуальный поэтапный план (контрольная дата 23.11.2026)

### Уже подготовленные контрольные этапы

- Phase 1: правильные HTTP 404, раздельная маршрутизация CRM/витрины, `robots.txt`, начальный `sitemap.xml`.
- Phase 2: отдельные публичные страницы категорий, товаров и новостей; канонические URL и динамический sitemap.
- Phase 3: компактная главная, чёрно-белая дизайн-система с синими/голубыми акцентами, увеличенные карточки, брендовые изображения, серверные страницы.
- Phase 4 (текущая): формы редактирования товара и SEO; запросы с частотностью и источником; расширенный XLSX/CSV импорт; атомарное потребление OTP; конфигурационный адрес главного администратора; проверка HTTP smoke-test.

Контроль Phase 4 на 23.11.2026: `npm run check` — 136 тестов пройдены, линтер проверил 71 файл без замечаний. HTTP smoke-test на отдельной временной SQLite-базе подтвердил главную, CRM, категорию, товар, health/ready, robots, sitemap и настоящие 404.
