# Исправление фотографий и вариантов товара — 24.11.2026

## Что изменено

- На публичной карточке цвет/вариант теперь является интерактивным переключателем. При выборе обновляется главное изображение, ALT-текст, цена, прежняя цена и подпись наличия.
- Галерея показывает общие изображения товара и изображения только выбранного варианта. Миниатюры остальных вариантов скрыты до выбора соответствующего цвета.
- Если выбранный вариант не имеет своего фото, используется только общее фото товара. Фотография другого цвета не подставляется. Если общего фото нет, показывается аккуратная заглушка; битая ссылка не оставляет сломанный `<img>`.
- Добавлена очистка HTML-сущностей и Markdown-маркеров из импортированных текстовых полей. Исправляется артефакт вида `**G&#x20;**Изображение не предоставлено`.
- В редакторе карточки товара добавлена кнопка «Варианты и фото». В нём можно создать/изменить/удалить вариант, редактировать цвет, SKU, цены, наличие и дополнительные атрибуты.
- Для каждого варианта можно загрузить несколько изображений или добавить проверенный URL. Уже загруженное изображение можно переназначить с уровня товара на конкретный вариант или обратно.
- Папочный импорт поддерживает структуру `images/<product-slug>/<variant-name>/01-main.jpg` и файл `images/<product-slug>/<variant-name>.jpg`. При однозначном совпадении изображение связывается с `variant_id`; неоднозначное совпадение возвращается для ручной проверки.
- XLSX/CSV-импорт теперь сначала создаёт/обновляет вариант, затем прикрепляет изображение к этому варианту. Строки без варианта остаются общими изображениями товара. Многоценовые строки и диапазоны не используются для автоматического расчёта итоговой суммы.

## Модель привязки

- `store_product_images.variant_id IS NULL` — общее изображение модели.
- `store_product_images.variant_id = store_product_variants.id` — изображение определённого цвета/исполнения.
- `store_product_variants` и колонка `store_product_images.variant_id` уже предусмотрены миграцией `004_vapelab_storefront.sql`; новая миграция базы данных не требуется.

Старые фотографии, которые ранее импортировались без `variant_id`, остаются общими изображениями. Они не назначаются автоматически цветам по догадке. Их можно переназначить в редакторе «Варианты и фото».

## Проверка

Команда `npm run check` выполнена успешно: линтер без замечаний, все 191 тестов прошли. Добавлены API-тесты на создание варианта, загрузку и переназначение изображения, вывод изображения варианта на странице товара и импорт изображения из папки цвета. Отдельные клиентские тесты проверяют, что расчёт не использует многоценовые строки и корректно считает итог для однозначной цены.

## Установка

Перед заменой файлов сделайте резервную копию проекта и базы данных. Распакуйте patch ZIP поверх текущего каталога проекта с сохранением структуры файлов, затем выполните:

```bash
npm run check
pm2 restart vapelab --update-env
```

После обновления откройте админку → Товары → карточка товара → «Варианты и фото». Для старых фотографий назначьте нужный цвет в поле «Привязать к». Новые фото лучше загружать сразу из соответствующей карточки варианта либо класть в подпапку с точным названием варианта.
