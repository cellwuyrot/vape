# Phase 4 — CRM, SEO и импорт каталога

Дата контрольной сборки: 23.11.2026

## Что изменено

### Редактор товаров в CRM

- Создание товара переведено с браузерных `prompt()` на форму в CRM.
- Редактирование основной карточки переведено на форму.
- Поля: название, SKU, бренд, тип, формат, описание, исходная цена, старая цена, подпись наличия, URL источника и запрос для подбора изображения.
- Новые карточки сохраняются черновиками; публикация выполняется отдельно.

### SEO редактор

- H1, SEO Title, Description, Canonical URL и поисковые фразы редактируются в одной форме.
- Добавлены счётчики длины и предварительный просмотр сниппета.
- Добавлен переключатель `robots_index`; он не публикует черновики.
- SEO-отчёт показывает редакционные замечания, статус публикации/индексации, количество изображений и категорий, наличие ALT и распределение поисковых запросов по частотным классам.
- SEO score — внутренняя оценка полноты полей, а не оценка позиции в поиске и не гарантия индексации.

### Запросы и частотность

- Для поисковой фразы сохраняются частотный класс, целочисленная частотность, поисковая система, регион, намерение, источник и дата проверки.
- Повторная запись того же запроса для той же карточки, поисковой системы и региона обновляется.
- Сравнение кириллических запросов выполняется с Unicode-нормализацией и русским регистром, а не только SQL `lower()`.
- Повторный импорт обновляет существующий запрос, а не дублирует его.

### Импорт XLSX/CSV

- В шаблон добавлены Canonical URL, управление индексацией, поисковая система, регион, намерение, источник и дата проверки частотности.
- В сопоставление колонок добавлены эти поля.
- Частотность принимается как целое неотрицательное число; десятичные и отрицательные значения отклоняются.
- Атрибуты варианта предварительно проверяются как JSON-объект до создания категории или товара.
- Уточнено сопоставление заголовков: слово «источник» само по себе больше не ошибочно трактуется как URL товара.
- Идентификация товара при импорте использует SKU, URL источника либо сочетание имени, бренда, типа и формата. Похожие названия с разными брендами/форматами не объединяются автоматически.

### Авторизация и главный администратор

- Первичный адрес главного администратора по умолчанию: `andycoulbot@gmail.com`.
- Если при инициализации обнаружены старые записи `superadmin` с другим адресом, они переводятся в роль обычного `admin`; конфигурационный адрес остаётся единственным `superadmin`.
- OTP-код потребляется атомарным SQL-обновлением. Один код не может быть успешно использован двумя параллельными запросами.
- Парольный вход остаётся отключённым. Никакого общего статического секрета или обхода OTP не добавлялось.

## Важная настройка существующей установки

В новой копии `.env.example` содержит:

```env
ADMIN_EMAIL=andycoulbot@gmail.com
```

При переносе в уже существующую рабочую папку `.env.example` не заменяет `.env`. Проверьте и вручную задайте `ADMIN_EMAIL=andycoulbot@gmail.com` в собственном `.env`, иначе сохранённое старое значение продолжит иметь приоритет.

При старте система создаёт/обновляет единственную запись главного администратора. Для входа всё равно требуется получить одноразовый код на указанный адрес. Настроить SMTP и убедиться, что ящик принадлежит владельцу проекта, необходимо до рабочего использования.

## XLSX шаблон

`templates/VAPELAB-products-template.xlsx`

Лист «Товары» содержит поля каталога и SEO. Лист «Инструкция» описывает правила заполнения. Новые поля частотности следует заполнять только по подтверждённым данным источника.

## Ограничения этой итерации

- Секретный пароль/магический обход `originkit` не добавлялся; вход для администратора идёт через OTP.
- Реальные изображения не скачиваются и не публикуются автоматически; найденное изображение требует подтверждения.
- Для поиска изображений по названию нужен настроенный Yandex Search API.
- Полноценная локальная React-сборка и оригинальный пакет OriginKit Hero 58 пока не установлены: в среде сборки DNS-запрос к npm Registry завершился `EAI_AGAIN`. Не считать их локально встроенными в этой версии.
- Browser E2E на desktop/mobile не выполнялся; формы проверены линтером и backend API тестами, требуется ручной визуальный просмотр.
- Blur и контроль 18+ не реализованы по отдельному согласованию и остаются отдельным этапом.
- Юридические тексты не менялись.
