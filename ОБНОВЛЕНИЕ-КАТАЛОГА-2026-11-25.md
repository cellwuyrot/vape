# Обновление каталога — 25 ноября 2026

## Что изменено

- В карточке товара: поиск по вариантам/SKU, фильтр страны, показ по 18 вариантов; без JavaScript все варианты остаются доступными. Ссылка `?variant=ID` восстанавливает выбор. Страны берутся из атрибута `country`/`страна` либо из распознанного суффикса названия варианта.
- В админке у варианта появилось поле «Страна (как указана в источнике)» и поиск по вариантам. Импорт CSV/XLSX принимает колонку «Страна варианта» / `country` в атрибут варианта. Страна — подпись источника, не обязательно страна производства.
- Опубликованный (`published`) товар открыт к индексации вне зависимости от старого флага `robots_index` и наличия на складе. Черновик, проверка и архив не публикуются; архивные URL возвращают 404. Существующий `canonical_url` остаётся действующим и может направлять поисковик на другой URL. Категории сохраняют собственные настройки индексации. Публикация не гарантирует включения поисковой системой.
- Sitemap учитывает опубликованные товары без фильтра по старому `robots_index`; canonical и условия попадания ссылок остаются важными. В SEO-редакторе товара удалён устаревший переключатель, который больше не влияет на индексирование товара. Старое поле базы и импорт сохраняются для совместимости.
- У пагинированных категорий canonical содержит номер страницы. Добавлены индексы миграцией 020.

**Важное изменение:** сразу после запуска новая версия открывает для индексирования *все опубликованные товары*, включая те, у которых ранее был `robots_index=0`. До выкладки проверьте список опубликованных позиций, их canonical и правомерность публичного представления/индексации для соответствующих категорий. Не публикуйте то, что нельзя открывать для индексации.

## Перегруппировка текущей базы

Рабочая база в архив не входит. Автоматическое слияние отдельных карточек по похожему названию не выполняется: без подтверждения это может повредить SKU, цены, фото, адреса и историю бронирований. В архиве есть инструмент анализа, а не готовый перенос карточек.

В режиме предварительного просмотра он находит названия **товаров** с распознанной страной в конце, группирует кандидатов по оставшемуся названию, бренду и типу; также предлагает заполнение отсутствующей страны для **вариантов** с распознанной страной в конце их названия. Названия, ID, ссылки, категории, фото и бронирования не меняются. Список стран ограничен словарём `server/catalog-country.js`; неизвестные или непривычно записанные страны требуют ручной проверки. Совпадение страны в названии не доказывает страну производства. Существующие атрибуты не перезаписываются, конфликты попадают в предупреждения.

```bash
# Все команды запускаются с той же конфигурацией БД, что и приложение.
node scripts/catalog-country-review.js --report=/абсолютный/путь/вне/проекта/country-preview.json
```

Изучите `product_candidates`, `changes` и `warnings` в отчёте (там могут быть коммерческие данные). После резервной копии, проверки на копии БД и в режиме обслуживания можно заполнить **только однозначные отсутствующие country у существующих вариантов**:

```bash
node scripts/catalog-country-review.js --report=/абсолютный/путь/вне/проекта/country-applied-plan.json --apply
```

Отчёт для `--apply` создаётся до транзакции и содержит план, а не подтверждение успеха: проверяйте код возврата и сообщение команды. Файл с уже существующим именем не перезаписывается. Перед применением план рассчитывается заново; остановите изменяющие данные процессы. Для полноценного объединения отдельных товаров сначала нужен утверждённый реестр соответствий старых и новых карточек, SKU, категорий, URL и зависимостей, затем отдельная проверенная миграция. Не удаляйте старые записи вручную без такой карты.

## Как перенести архив в Git

Архив — исходный проект, не Git-репозиторий и не серверная база. Сначала разверните его во временную папку **на компьютере с существующим локальным клоном нужной ветки**, сравните изменения и перенесите их в корень этого клона. Не копируйте `.env`, базы, пользовательские файлы и резервные копии; не используйте `rsync --delete`.

Пример при установленном `rsync` (замените пути):

```bash
unzip /путь/vapelab-updated.zip -d /tmp/vapelab-update
cd /путь/к/вашему/локальному/git-репозиторию
git status
rsync -av --exclude='.env*' --exclude='data/' --exclude='uploads/' \
  --exclude='node_modules/' --exclude='backups/' \
  /tmp/vapelab-update/vape-main/ ./
git status
git diff --stat
git diff
# Проверьте также новые файлы в git status.
npm ci --omit=dev
npm run check
# Добавьте только проверенные файлы проекта, без базы/секретов/загрузок.
git add -A
git diff --cached --stat
git commit -m "Improve catalog variants and indexing"
git push origin HEAD
```

Если локальная версия репозитория отличается от исходного архива, не перезаписывайте её вслепую: сначала сравните и объедините изменения. `git pull` на сервере не получит архив автоматически — сначала нужен commit и push в ветку, отслеживаемую сервером.

## Обновление сервера через PM2

В исходных документах проекта указан `/var/www/vapelab`, но это пример. **В архиве нет доступа к вашему серверу**, поэтому наличие `/var/www/vapelab/app` не подтверждено. Найдите реальный `pm_cwd` и путь скрипта в `pm2 describe vapelab`, затем проверьте, где Git-корень и `package.json`; возможно, это `/var/www/vapelab/app`.

```bash
pm2 list
pm2 describe vapelab
# Вместо пути ниже подставьте реальный pm_cwd из вывода PM2:
cd /var/www/vapelab/app
git rev-parse --show-toplevel
pwd
ls package.json
git status --short --branch
node -v
```

Нужен Node.js 22 или новее. Убедитесь, что серверная ветка отслеживает ветку после push, нет несохранённых изменений и миграция `020` не занята иной версией. Не продолжайте при расхождениях.

Перед командами определите актуальные `DATABASE_URL`, `DATA_DIR`, `STORAGE_DIR` и учётную запись процесса: `.env` читается из **текущего рабочего каталога**, но переменные окружения PM2 имеют приоритет. Команды backup/migrate должны получать те же значения, что работающий процесс; не выводите секреты в публичные логи. Сохраните старый commit и резервные копии базы, хранилища и `public/uploads/catalog` вне репозитория; проверьте восстановление. Наличие и настройки Postgres, S3 и постоянных дисков определяются по вашей конфигурации. Если конфигурация неизвестна, остановитесь и уточните её до обновления.

После юридической проверки, проверки ветки и успешного backup (ниже каждый шаг выполнять только при успехе предыдущего):

```bash
# Из реального рабочего каталога приложения, с тем же окружением БД/хранилища.
pm2 stop vapelab
npm run backup
# Проверьте сообщение об успешной проверке копии и отдельно сохраните старые
# public/uploads/catalog и иные не входящие в backup пользовательские файлы.
git pull --ff-only
npm ci --omit=dev
npm run migrate
pm2 restart vapelab --update-env
pm2 logs vapelab --lines 50
```

Затем проверьте `curl -fsS http://127.0.0.1:ПОРТ/api/health` и `/api/ready`, CRM, существующую карточку с вариантами, её фотографии, цену, ссылку выбранного варианта, sitemap и архивный товар. Используйте реальный `PORT` приложения. Если что-то не прошло — не продолжайте обработку базы; восстановите согласованные код, базу и файлы из проверенной копии. Не используйте `npm run reset`.

Новая версия содержит готовый `public/react-app` из исходного архива; для данных изменений пересборка React-витрины не нужна. `npm ci --omit=dev` устанавливает зависимости корневого сервера. Процесс объединения отдельных товарных карточек и перевод полного публичного API/поиска на серверную пагинацию в это обновление не входят. Фильтрация вариантов выполняется в браузере: сервер по-прежнему выводит все варианты товара в HTML; это сокращает видимый список, но не размер исходного HTML.
