# VAPELAB — приёмка пользовательского поиска, карточки товара и чата

## Что добавлено

- Общая строка поиска в шапке React-витрины, резервной HTML-витрины и серверных SEO-страницах.
- Подсказки поиска по опубликованным товарам: название, SKU, бренд, тип, формат, описание, характеристики, категории и SEO-поля; ранжирование точных/частичных совпадений и допуск одной опечатки.
- Полная страница `/search?q=...` с результатами по 24 товара и серверной пагинацией через `/api/store/search`.
- Публичный чат `/api/webchat/messages`, хранящий диалоги и сообщения в существующих `conversations`/`messages` с каналом `webchat` (подпись в CRM — «Чат сайта»). Отдельная таблица и отдельная CRM-сущность не создаются.
- Сессионный токен чата подписан штатным HMAC-секретом, не раскрывает публичный API доступа по одному ID диалога и действует 30 дней.
- Новый гостевой диалог требует согласия на обработку персональных данных; при наличии действующей пользовательской сессии применяется уже сохранённое согласие.
- Ответ сотрудника из CRM сохраняется в общей таблице сообщений и появляется в чате посетителя при опросе.
- В карточке товара блок бронирования вынесен из двухколоночной сетки. Заголовок находится над полями, форма и кнопка занимают отдельную ширину.
- Технические заглушки описания и цены скрываются. Значение цены выводится только если в `price_raw`/цене варианта действительно есть непустое исходное значение, не являющееся заглушкой. Суммы не вычисляются и не угадываются.
- Некорректные URL изображений не вставляются в карточку; при отсутствии безопасного изображения используется визуальная заглушка.

## Локальная установка

1. Остановить текущий backend (`Ctrl+C`).
2. Сделать резервную копию проекта и папки `data`.
3. Распаковать обновление поверх исходников, сохранив `.env`, `data` и локальные зависимости.
4. При отсутствии зависимостей выполнить `npm install` в корне и `npm --prefix storefront-react install`.
5. Собрать витрину: `npm run build:storefront`.
6. Проверить проект: `npm run check`.
7. Запустить backend: `npm start`.

## Ручная приёмка в браузере

### Карточка товара

- Открыть опубликованный товар по `/product/<slug>`.
- Проверить, что заголовок «Забронировать товар» находится над формой, форма не сжата в колонку, кнопка целиком видна на широком экране и мобильной ширине.
- Для товара без цены проверить, что не показываются надписи «Не указана» и «Подпись цены в исходных данных».
- Для товара с реальной строкой `price_raw` проверить, что значение показывается под подписью «Цена».
- Для пустого/служебного описания проверить, что техническая заглушка не видна.

### Поиск

- Ввести часть названия, бренд или SKU в верхнюю строку поиска.
- Проверить подсказки с изображением (если есть), названием, метаданными и переходом в товар.
- Нажать Enter: должен открыться `/search?q=...`.
- Проверить число результатов, переходы страниц и отсутствие дубликатов между страницами.
- Повторить на мобильной ширине и на SEO-странице товара/категории.

### Чат с администрацией

- В приватном окне открыть сайт, развернуть «Связаться с нами».
- При первом гостевом обращении проверить форму контакта и обязательное согласие с политикой.
- Отправить сообщение. В CRM открыть «Диалоги», выбрать канал «Чат сайта» и открыть новый диалог.
- Ответить из CRM. Убедиться, что ответ появился в том же окне чата посетителя без перезагрузки страницы.
- Повторить после входа в личный кабинет: существующая авторизация и согласие пользователя должны позволять открыть чат без создания отдельного аккаунта.

## Что требуется до production

- Заполнить, проверить и опубликовать политику конфиденциальности; до этого гостевой чат корректно не должен обходить требование согласия.
- Подтвердить адреса, телефон и реальные условия обработки персональных данных.
- Подключить SMTP, проверить доставку писем и настроить Telegram Bot/API, если нужны дополнительные уведомления.
- Проверить актуальность каждой цены и наличия из выгрузки владельца. Старые значения в `price_raw` являются исходными данными и не считаются автоматически подтверждёнными.
- Проверить UI в реальных браузерах/устройствах и провести smoke-тесты HTTPS, резервного восстановления и доступа к CRM на тестовом production-стенде.
