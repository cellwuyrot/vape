# VAPELAB Stage 4 — журнал поэтапных изменений

## Checkpoint 1 — маршрутизация и серверная основа

- Убрана подмена любого неизвестного пути оболочкой CRM.
- `/` обслуживает витрину, `/crm` — CRM.
- `/crm/` перенаправляется на `/crm` кодом 308.
- Неизвестные HTML-адреса получают HTML-страницу с HTTP 404 и `noindex`.
- Неизвестные API-адреса получают JSON 404.
- Статические файлы выдаются только при наличии файла внутри `public/`; HTML-файлы доступны только по явным маршрутам.
- Добавлена защита от декодированных traversal-путей и symlink-выхода за пределы public-каталога.
- Добавлены `/robots.txt` и `/sitemap.xml`.
- CRM получает `X-Robots-Tag: noindex, nofollow`.
- Добавлена проверка production `PUBLIC_URL`: требуется абсолютный HTTPS origin.
- Добавлены тесты для 404, служебных SEO-файлов, redirect и HEAD.

## Checkpoint 2 — публичные категории и карточки товаров

- Добавлена миграция `009_public_category_pages.sql` с управляемыми SEO-страницами категорий и связями с исходными категориями.
- Созданы 14 коротких пользовательских страниц для 18 корневых категорий; исходные категории остаются отдельными сущностями в базе.
- Созданы отдельные маршруты для пяти вложенных категорий.
- Созданы server-rendered страницы `/product/:slug` для опубликованных товаров.
- Созданы server-rendered страницы `/news/:slug` и обработка одобренных информационных страниц `/page/:slug`.
- На страницах выводятся уникальные H1, title, description, canonical, robots, Open Graph и breadcrumbs.
- Каталог на главной, страницы категорий и карточки товаров получили внутренние ссылки на отдельные URL.
- Старые адреса корневых категорий перенаправляются на короткие канонические URL.
- Пустые категории остаются доступными для навигации, но получают noindex и не включаются в sitemap.
- Sitemap динамически собирает только опубликованные и индексируемые категории, товары, новости и одобренные информационные страницы.
- Внешние canonical URL и URL с query/hash не включаются в sitemap.
- Внешние URL источника в карточках принимаются только по HTTP(S).
- Добавлен полный crawl-тест всех категорий и товаров.

## Следующий checkpoint — визуальная архитектура витрины

- Упростить главную страницу: основная информация о компании, история и направления; далее короткие ссылки на ключевые категории.
- Вернуть чёрно-белую палитру с небольшими синими и голубыми акцентами.
- Перевести только публичную витрину на отдельную React-сборку, если подтвердится совместимость, и оставить CRM/backend на текущем Node.js-контуре.
- Интегрировать настоящий OriginKit Hero 58 и выбранные реальные React Bits-компоненты, а не CSS-имитации.
- Увеличить карточки товаров и сделать компактную навигацию категорий.
- Добавить skeleton states и плавные переходы с поддержкой `prefers-reduced-motion`.

## Checkpoint 3 — короткая главная и визуальная система

- Главная сокращена до презентации компании, направлений, шести ключевых переходов к каталогу, сворачиваемой полной навигации, новостей и контактов.
- Убран вывод полного каталога товаров с главной; товарные карточки остаются на самостоятельных страницах категорий.
- Восстановлена бело-чёрная основа с ограниченными синими и голубыми акцентами.
- Подключён предоставленный логотип в шапке, Hero и подвале; SVG favicon теперь содержит фирменный знак.
- Добавлена адаптивная мобильная навигация для серверных страниц категорий, товаров и новостей.
- Hero получил particle-wave canvas-анимацию в визуальном направлении OriginKit Hero 58. Это адаптация, не исходный компонент OriginKit.
- Реальный React-компонент React Bits SpotlightCard адаптирован для товарных карточек: React `useRef`, слежение за указателем и CSS custom properties; при ошибке загрузки внешнего React runtime сохраняется обычная HTML-карточка.
- Добавлено уведомление об авторстве и лицензии React Bits в `docs/licenses/REACT-BITS-NOTICE.md`.
- Карточки товаров увеличены до 3 колонок на широких экранах, 2 на планшете, 1 на узком мобильном.
- Добавлены тесты короткой главной, ключевых категорий, реального SpotlightCard-модуля, favicon и мобильной навигации.
- Анимация Hero и Spotlight учитывают `prefers-reduced-motion`; Hero приостанавливается при невидимой секции или скрытой вкладке.

### Известные ограничения checkpoint 3

- Точный исходник OriginKit Hero 58 не установлен; нужен отдельный React frontend/build pipeline и доступ к CLI.
- React Bits runtime сейчас загружается браузером с esm.sh; для production требуется локальная сборка/бандлинг React.
- Chroma Grid отложен до получения оригинальных фотографий товаров.
- Полноценный визуальный браузерный screenshot QA в контейнере не пройден из-за политики Chromium, блокирующей локальный HTTP URL. Есть статические проверки и живой HTTP crawl; требуется визуальная проверка в пользовательском браузере.
- Блюр и возрастные ограничения остаются отложенными.

## Phase 4 — CRM / SEO / importer hardening (23.11.2026)

- Создание и редактирование товаров в CRM переведены на полноценные формы вместо `prompt()`.
- SEO редактор получил H1, Title, Description, Canonical, robots index, счётчики и предварительный просмотр сниппета.
- SEO summary дополнено количеством опубликованных/indexable страниц, пустых H1 и отсутствующих изображений; score явно описан как проверка наполненности, не прогноз позиций.
- Добавлена Unicode-нормализация поисковых фраз для кириллицы; повторная запись по товару/поисковой системе/региону обновляется.
- XLSX/CSV импорт расширен метаданными частотности, Canonical и robots index; обновлён шаблон `templates/VAPELAB-products-template.xlsx`.
- Валидация JSON варианта и частотности выполняется до создания категории/товара.
- Устранена неоднозначность маппинга: `Источник частотности` не попадает в поле URL источника.
- Повторный импорт не дублирует поисковые фразы; товары с похожим названием и разными брендами/форматами остаются разными записями.
- OTP consumption переведён на атомарные SQL-обновления; параллельное применение одного кода тестируется.
- Смена `ADMIN_EMAIL` оставляет только одного `superadmin`; прежние superadmin-профили переводятся в admin.
- Главный администратор по умолчанию — `andycoulbot@gmail.com` (переопределяется `.env`).
- OriginKit локальная установка остаётся заблокированной DNS-ошибкой npm Registry; текущая Hero-wave версия документирована как адаптация, не оригинальный пакет.

- Добавлено отдельное приложение React/Vite в `storefront-react/`; backend зависимости остались пустыми.

## Phase 6 — уточнение распространения визуальных компонентов

- Upstream-исходник React Bits SpotlightCard исключён из текущего передаваемого ZIP; подготовлен прямой локальный installer из официального registry и adapter.
- До установки React Bits используется отдельный fallback VAPELAB без upstream source.
- OriginKit Hero 58 не включён и не объявляется установленным: требуется авторизация CLI владельца.
- Vite production bundle не подтверждён, пока в рабочей среде недоступен npm Registry.
